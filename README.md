# Azeroth Complete

A completionist tracker for **World of Warcraft: Forever**. It shows, in one window, what is
left to do in the world: quests by zone and by quest chain, the full recipe catalogue of
every profession, dungeons and raids with their bosses and quests, Legacy challenges, and
the account's collections (mounts, pets, toys, appearance sets, titles).

The addon is localized: English and French today, and every text about game content
(quest titles, item, spell, zone and faction names...) comes from the game client itself,
in the language of the player's client.

![Emblem](art/emblem.png)

## Features

- **Quests**: zones grouped by continent, with their completion; quests grouped into chains
  that unfold; for each quest its status, level, prerequisites, follow-ups, giver and turn-in
  NPC (with a map waypoint), experience and reputation rewards.
- **Professions**: the complete catalogue of each profession for the Forever client, the
  recipes already learned, the reagents, and how to obtain each recipe (trainer, vendor,
  drop, quest).
- **Dungeons and raids**: bosses defeated and instance quests completed.
- **Legacy challenges**, read from the game.
- **Collections and toys**: what is owned and what is missing, with the source of each item.
- **Account or character tracking**: the account view merges the progress of every character
  that logged in with the addon enabled; a faction selector shows the other faction's quests.
- **Within reach**: the character view keeps only what the character can do (its race, its
  class and the professions it has learned), with the counts to match; a switch shows
  everything.

## Installation

Download the zip of the [latest release](../../releases/latest) and extract it into
`World of Warcraft/_forever_/Interface/AddOns/`, so that the folder
`Interface/AddOns/AzerothComplete` contains `AzerothComplete.toc`.

## Usage

Open the window with the minimap button, the addon compartment or `/azc`.

| Command | Effect |
| --- | --- |
| `/azc` | open or close the window |
| `/azc diag` | list which game features the client provides |
| `/azc log [count]` | print the last log entries |
| `/azc debug` | toggle detailed logging |
| `/azc rescan` | read the character's progress again |
| `/azc scale <0.5-2>` | resize the window |
| `/azc minimap` | show or hide the minimap button |
| `/azc reset` | clear the cache of game texts |
| `/azc clearlog` | clear the log |

Learned recipes are read from the spellbook at login and from the profession window when it
opens: opening each profession once completes the catalogue.

## Logs

The addon keeps a log in its saved variables, written by the game on `/reload` and on logout:
`WTF/Account/<account>/SavedVariables/AzerothComplete.lua`, table `AzerothCompleteDB.log`.
At every login it records which client APIs exist, which helps when a feature behaves
differently on the Forever client.

## Data

The files of `AzerothComplete/Data/` are generated by `tools/build_data.py` from two sources:

- [QuestieDB](https://github.com/Questie/QuestieDB) (GPL-3.0): the quest structure (zones,
  levels, prerequisites, quest givers) and the sources of recipe items. Only identifiers and
  numbers are kept, plus English names used as a last resort when the client cannot provide a
  text.
- The client tables of the targeted WoW Forever build, as published by
  [wago.tools](https://wago.tools): recipes, instances, encounters, collectible identifiers,
  the exploration overlays of the zone maps, and the few localized strings the client API does
  not expose. Artwork the client tables reference is kept only when the build ships the file.
  A zone whose map cannot be drawn shows a loading screen instead: that of the map it is the
  whole of, or of an instance it holds; a class category shows the talent background of the
  class, and any other category a loading screen chosen for it in the generator.

```sh
python -I tools/build_data.py --build 1.60.1.70888
```

Downloads are cached in `.cache/`; delete it to refresh them.

## Development

The tests load the addon on top of an emulation of the WoW API (`tests/wow_stub.lua`), log
in, open the window and go through every tab. They need a Lua 5.1 interpreter:

```sh
lua5.1 tests/run.lua
AC_TEST_LOCALE=frFR lua5.1 tests/run.lua
```

To try a change in the game, copy `.env.example` to `.env` (ignored by git) and set
`WOW_GAME_DIR` to your `_forever_` folder, the one that holds `Interface/AddOns`. Then
`tools/install.sh` copies the addon there as a release would lay it out, with the commit in
place of the version so that the log tells which revision is running. A directory given as
argument takes precedence over `.env`:

```sh
tools/install.sh
tools/install.sh "D:/Games/World of Warcraft/_forever_"
```

Lua changes are picked up by `/reload`; a change to the TOC or a new file requires restarting
the game.

The emblem texture is produced from `art/emblem.png` by `python -I tools/make_emblem.py`.

## Releases

Merging a pull request into `master` publishes a release named after the version in the
pull request title (for example "Azeroth Complete v0.1.0"), with the packaged addon attached.
